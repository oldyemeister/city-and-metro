## 2026-11-18 · 上海建线期间的持续负载与其他简化方式

performance / ca776f7，上游基线 bd76a32。玩家在 M2 Pro MacBook 上发现持续游玩后风扇加速，建线与重算期间尤为明显。只读核对工作区代码、342 站既有首轮道路输入和先前浏览器 CPU 记录。本轮写入两份交接文档，无游戏、存档或系统设置改动，无新增压力测试或提交。未取得玩家现场的温度、功耗或风扇转速。

**优先观察建设预测的调用次数。** js/ui.js 的草案版本变更后静止超过 1.2 秒、停止拖动且符合条件，就会自动请求效果预测。继续编辑会让在算的预测失效。js/sim.js 的一次完整预测要比较两张线网、两种日型和四个时段，每个时段最多 6/4/6/3 轮，可提前收敛。js/game.js 确认建设会触发正式结算，并在交通模型就绪且无待复核事项后计算建设影响报告。三种工作目的不同。可优先比较同一建线操作下的当前默认与手动请求草案预测，保留正式运营结算，再考虑按需生成报告。之前 342 站约 15 秒基准测的是加开交路，未直接计量拖动、反复草案编辑和建后报告。

**并行度与噪声。** 先前上海 278 站存档的隔离 Chrome 实测，每种场景和配置各三轮。推进一季度时，4 → 2 个道路 Worker 后，整个浏览器的区间采样峰值中位数为 571% → 386%（100% 约为一个逻辑核心），完成时间 9.64 → 16.87 秒。同场景快照的客流、经济指标与交通数组一致。当前界面没有道路 Worker 数设置；可选低并发模式属于后续试验。风扇验证需在同一机器同一存档重复相同建线操作，记录 CPU 占用、持续时间，以及功耗或风扇转速；前述历史数据只支持 CPU 与用时的取舍。[重复对照](../../evidence/road-workers/repeated-SjxJDO/summary.json)

**路网候选。** 在 Shanghai 2015 输入上，把全部小区接入点作为受保护顶点，按物理双向路段建邻接表。剔除没有接入点的连通分量，再递归剪掉无接入点的叶子，可将 15,136 条无向路段减至 14,358 条（减少 778 条，5.14%）。还可研究合并中间无岔口、无接入点的连续路段，须按每轮有向拥堵时间加总并还原每段车流，复核同耗时路线的先后顺序。更长期可观察可定制收缩层次（CCH），固定拓扑预建捷径，每轮更新拥堵权重，再把车流展开回原路。该方法尚无本存档的耗时与温升实测。[原始交通分配研究](https://drops.dagstuhl.de/entities/document/10.4230/LIPIcs.SEA.2018.27)
