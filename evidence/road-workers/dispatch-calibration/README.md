# 道路 Worker 的 WASM 启用阈值

当前版本按玩家要求使用 **10%**。下表保留 11% 校准时的历史实测。用相同的原始分块记录分别套用 10% 和 11% 规则，上海 2010 三个月、一年、自然跨月的 5,056 个块均选择相同内核，最低密度 11.331%。伦敦新增 72 个 WASM 块，季度 32 个、年度 8 个、自然跨月 32 个。这个计数只说明执行路径变化。10% 的边界与兼容性可直接运行 `node evidence/road-workers/dispatch-calibration/check-compatibility.mjs` 复核。

在上海 1 号线加开“大站快车”后，浏览器实际显示了“交通数据正在更新，居民出行选择正在重新计算…”。离线用同一游戏操作和 4 个真实道路 Worker 回放到模型完成更新，共 32 次道路分配、1,024 个块，密度 11.484% 至 45.317%。75% 会全部走 JS，11% 与 10% 会全部走 WASM。浏览器在时限内观察到交通数据已可用而横幅仍显示，未取得横幅实际清除时间。[浏览器现场](../dispatch-validation/fare-browser-zuZyaL/results.json) · [同一操作的完整调度记录](../dispatch-validation/network-banner.json)

2026-11-17，在 `performance` 分支的 `f9706d4` 上，将单个道路计算块启用现有 WASM 内核的终点密度从 **75% 调为 11%**。密度等于该块实际请求的起终点对数除以「块内起点数 × 全图分区数」。游戏代码改动为 `js/sim.js` 中的一处常数，构建另外更新了模拟指纹和资源清单。

同一“加开”操作使用游戏引擎和四个 Node 道路 Worker 做两轮反序对照，从确认交路到模型更新完成，75% → 10% 分别为 9.872 → 7.619 秒、9.944 → 7.493 秒，平均缩短 23.74%。完整交通、经营数据一致。这里的计时不含浏览器绘制和横幅刷新。[模型耗时与一致性](../dispatch-validation/network-banner-comparison.json)

## 存档与一致性

上海经营存档从 2010-01-16 开始，有 278 座车站。小路网使用内置伦敦 1860-01-01 的经营开局，0 座地铁站。两者均从本地只读测试副本加载。第一次跨月工作日道路分配的特征如下。

| 指标 | 上海 | 伦敦 |
| --- | ---: | ---: |
| 道路节点 | 8,747 | 2,091 |
| 平均每个起点请求的终点数 | 303.7 | 128.5 |
| 每个起点的终点密度，全体起点加权平均 | 21.03% | 7.49% |
| 吸收一半驾车需求的终点分区数 | 50 | 14 |
| 每个起点的终点相对其重心的均方根半径，按驾车需求加权后取中位数 | 6.29 km | 2.69 km |

伦敦的“小”指道路图规模；其地理范围为 49 × 35 km，上海为 38 × 38 km。离线回放将两种 Worker 与同步版逐字节核对，涵盖每个请求的时间、里程、不可达值、32 个块的路段流量及按块顺序合并的全图流量。[上海分布](shanghai2010-od.json) · [伦敦分布](london1860-od.json) · [终点集中度](../dispatch-validation/destination-spread.json) · [逐字节验证脚本](../dispatch-validation/verify-allocation.mjs)

浏览器每次从相同导出载入，先核对地图、日期、站数和实际 Worker 数。每对试验的起点和终点均核对了 8 个时段的 232 份交通数组的类型、长度和字节 SHA-256，时段统计，43 份日汇总和车站、设施数据摘要，20 项经营与交通指标，完整序列化经营状态、月度历史、账本、任务、合同、车队、线网与时钟。同时核对每次分配、每个块的规模和实际执行内核。11 组强制 JS/WASM 配对和 4 次正式策略对照均一致。[主试验独立核验](browser-LXmOn4/verified-summary.json) · [上海反序核验](browser-VAsFyM/verified-summary.json)

## 玩家操作实测

macOS ARM64，Chrome for Testing 156.0.8078.80，可见的隔离标签页，测试自动保存关闭。顺序执行，桌面实测均为道路/方式选择/地铁 4/2/2 个 Worker。三个月和一年从点击游戏按钮计到 `jumpDone`。自然跨月在暂停状态下按正常日结算推进到 1 月 31 日，置于 23:59，再以 1 倍速跨月，从实际进入日结算计到新月份交通和任务复核完成。加载、准备日期和计算校验和均在计时外。伦敦年度实测运行了完整 12 次月结算，游戏既有的长跳交通刷新规则使道路计算量少于三个月快进。

| 上海 | 自然跨月 | 256 | 2.943 / 2.412 | 3.127 / 2.342 | −21.7% |

## 为什么选 11%

- 上海首轮三个操作共有 5,056 个块，全部达到 11%，全部低于旧阈值。密度 11% 至 20% 的块处理时间中位数由 35.1 降至 26.1 ms，更高密度的块由 36.9 降至 27.2 ms。伦敦仅 408/2,560 个块达到 11%，这组由 2.6 降至 2.1 ms，低于 5% 的块则由 0.1 升至 0.3 ms。[浏览器密度分组](browser-LXmOn4/verified-summary.json)
- 离线扫描中，11% 在上海、伦敦、青湾三份原样分配上分别选中 32、5、32 个块。69 个块的 WASM 耗时中位数全部优于 JS。作为敏感性检查，把青湾每个起点限制为最近 12 个原有终点，密度正好 10%，其中 4 个试验块有 3 个在 WASM 下较慢。升到 12% 又会漏掉上海原样分配的 2 个受益块。11% 是这些样本支持的折中，精确交点随路网、终点分布和设备变化。[阈值扫描](../dispatch-validation/thresholds.json)
- 重载已构建的 11% 版本，核对实际模拟指纹及正式 Worker 源码。桌面季度快进，上海 864/864 个块走 WASM，**7.307 秒**，比首轮 JS 少 **23.1%**；伦敦 160 个块走 WASM、864 个走 JS，**1.257 秒**，比首轮 JS 多 **38 毫秒**。这是该策略各一次的端到端验收。[正式策略与路径计数](browser-LXmOn4/verified-summary.json)

## 兼容性与复核

生产代码沿用内嵌 WASM、现有 JS 求解器和 Worker 分配策略。真实 Chrome 的 390 × 844 触屏模拟使用 2/1/1 个 Worker，伦敦季度有模块时耗时 1.505 秒（160 个 WASM 块），禁用模块时 1.595 秒（1,024 个 JS 块）。两次数据均与桌面 JS 参照一致。离线检查还覆盖模块克隆、实例化、求解失败，以及无 Worker 时整时段切回主线程。手机性能证据限于 Chrome 触屏模拟，未在实体 iOS/Android 设备上测量。

在仓库根目录复核留存的数据与当前发布代码：

```sh
node evidence/road-workers/dispatch-validation/verify-browser.mjs evidence/road-workers/dispatch-calibration/browser-LXmOn4
node evidence/road-workers/dispatch-validation/verify-browser.mjs evidence/road-workers/dispatch-calibration/browser-VAsFyM --partial
node evidence/road-workers/dispatch-calibration/check-compatibility.mjs
node scripts/build-road-kernel.mjs --check
node scripts/build.mjs
node scripts/verify-game.mjs
```

两份本地复测导出位于 `savedgames/test/Shanghai-2010-01-278.cmsave.json` 和 `savedgames/test/London-1860-01.cmsave.json`，SHA-256 记录在主报告的 `fixtures` 中。新一轮可使用 `browser.mjs --large=<上海导出> --small=<伦敦导出> --policy=evidence/road-workers/dispatch-calibration/policy.json`（以 Node 从仓库根目录运行）。默认浏览器预算为 120 秒，本轮在原对话授权的 480 秒内进行。第一次试跑的快照调用遗漏导致空快照，已修正，首个无效样本剔除并重测。所有有效运行合计至同一截止时间前的 420.824 秒，零运行时或资源错误。最终隔离页面恢复正式道路调度，暂停在上海 2010-02-01 00:00，交通已结算。
